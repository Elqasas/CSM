{% load query %} {% comment %} The account table, defined once and used by both the account list and the analytics roster. Two copies of this markup would drift the first time a column changed, and the two pages would quietly start describing the same accounts differently. Every column heading sorts, and both pages sort by the same keys because both go through `accounts.filters.apply_sort`. The links carry the query string with them: a bare `?sort=name` - which these used to be - threw away the search and the filters, so sorting a filtered list silently unfiltered it. No arrows. The sorted column is marked with `aria-sort`, which a screen reader announces and the stylesheet weights, rather than putting a glyph beside nine headings. Expects: accounts AccountPresenter objects, never raw models - the health columns go through the presenter, which is what makes the gating real. shows_health whether to render the status dot and the health column. row_actions whether each row carries its own actions menu. The account list does; the analytics roster deliberately does not - it is a report you read, and a delete beside a chart is a misclick. sortable whether the headings link. Both real pages pass True; it stays a flag so a table embedded somewhere with no query string of its own cannot offer links that would not work. empty_title / empty_body what to say when there is nothing, since "no accounts yet" and "nothing matches this filter" are different situations. {% endcomment %}
